# 量化学习计划追踪器 (Plan Tracker)

> 双轨学习系统 — 主计划 134 天（Python → 量化 → AI → 部署 → Agent）+ 数学轨道 61 天 — 内置每日 Prompt；阶段五至七采用整日完成标记，其余保留已有任务清单，进度落成仓库里的一个 JSON 文件。

> **状态**：本地开发完成，进度已落成 `progress/current.json`（**不在 git 里**）。
> **下一步**是搬到一台 Ubuntu server 常驻 —— 见 **[docs/部署.md](docs/部署.md)**。

## 项目概览

一个网页应用，用于追踪以 Python、量化研究和 AI 应用为载体、逐步建立通用系统素养的学习计划。核心理念：**不记语法，让 AI 写代码；你学的是判断力、设计能力和领域理解。**

页面本身是纯前端（无构建、无框架），另有一个几十 KB 的本地小服务负责把进度落盘 —— 详见「本地运行」。

- **主轨道**（134 天，约 3 小时/天）：Python → 量化数据处理 → 工程基座 → 金融数学 → 产品思维 × AI 核心技术 → 回测与策略开发 → 服务部署 → Agent 架构
- **数学轨道**（61 天，约 25 分钟/天）：函数 → 概率分布 → 统计推断 → 线性代数 → 计算思维数学 → 进阶数学
- 两条轨道互相独立，Main 教「怎么用」（工具化），Math 教「为什么」（原理化）

    ├── router.js       # Hash 路由 — #overview / #main / #math / #main-12 / #math-34 / #read-main-56
    ├── render.js       # 渲染逻辑 — 首页热力图、侧栏导航、日详情、总览页思维导图
    └── app.js          # 应用入口 — 初始化、Toast、键盘快捷键、浮动提示

└── plan_server.py      # 本地服务（仅标准库）— 静态服务 main/ + 进度文件读写 API

└── current.json        # 当前进度；history/<日期>.json 是每天的自动快照

### 数据流

```
main/js/data.js                       ← 唯一数据源（MAIN_PLAN + MATH_TRACK）。改计划＝改这个文件
        │
        ▼  store.js 启动时一次性读进内存
progress/current.json                 ← 用户进度（唯一的真相，浏览器只是显示它）
        │                                ▲
        │                                │ 防抖 400ms 后 PUT 回写
        ▼  render.js                     │
DOM                                   ← 热力图 / 日详情 / Prompt 区 / 任务列表
                                      Store.toggleTask() 等写操作
```

> **`main/js/data.js` 没有生成器** —— 它是手工编辑的。`mine_outline.py` / `math_outline.py`
> 是它的**人类可读版大纲**（带缩进，比 332KB 的 `data.js` 好读得多），**不参与生成**；
> 改计划就是直接改 `data.js`。
> 曾经的同步脚本在 `archive/scripts/`，**已归档、跑不通** —— 它们的路径写死在旧的 Windows 目录，
> 而且输出目标是根目录那个已经死掉的 `app.js`（不是 `main/js/data.js`），
> 跑起来会「打印成功但页面一个字没变」。**别去修它们。**

**为什么是「启动时一次性读进内存」**：`render.js` 是**同步**调用 Store 的读接口的
（`isTaskDone` / `isDayDone` / `getLevel` / `getDoneCount` 都在渲染函数里同步取数）。
所以异步读文件这条路走不通 —— 只能在启动时把整个进度读进内存，之后所有读操作同步返回。

## 核心特性

- **Glassmorphism UI** — 深色渐变背景 + 毛玻璃卡片 + 镜面高光，全部 token 化可配置
- **热力图日格子** — 5 档完成度（未开始 / 开了个头 / ≥33% / ≥66% / 全部完成），hover 浮动提示
- **思维导图总览** — 左列 134 天主计划树结构，右列 61 天数学按 syncMain 自动对齐定位
- **SyncMain 交叉引用** — 数学轨道每天标注主计划首次使用该概念的位置，可一键跳转
- **进度存进文件** — 落成 `progress/current.json`，换机器、换浏览器都跟着走
- **能断网** — 服务没起来时自动退回 localStorage，右下角徽章变黄告诉你；服务回来 3 秒内自己同步
- **键盘快捷键** — `Ctrl+Enter`（Mac 上 `⌘+Enter`）勾掉下一个还没做的任务，`Esc` 返回首页
- **连胜追踪** — 两条轨道合并计算连续学习天数（错过一整天就断；当天勾满记一笔，全点灭就退账）

## 本地运行

**双击 `启动学习计划.command`（Mac）或 `启动学习计划.bat`（Windows）** —— 会自动起服务并打开浏览器，
进度实时写进 `progress/current.json`。

需要 python3，Mac 和 Windows 都没有的话会提示怎么装。**没有构建步骤，没有第三方依赖。**

> Mac 首次双击可能被 Gatekeeper 拦下（提示"无法验证开发者"）→ **右键 →「打开」→ 再点一次「打开」**。
> 命令行的话 `python3 tools/plan_server.py` 也一样，参数见 `--help`
> （`--host` 默认 `127.0.0.1`、`--port` 默认 `8000`、`--no-browser` 不自动开浏览器）。

也可以**直接双击 `main/index.html`** —— 那种情况够不着文件，会自动进「离线模式」，
进度只存在这个浏览器里，右下角徽章是黄的。等哪天双击了启动器，进度会自动写进文件。

### 进度存在哪

| | |
|---|---|
| 当前进度 | `progress/current.json` |
| 每日快照 | `progress/history/<日期>.json`（每次写入顺带存一份，写坏了可以拿回来） |
| 格式 | `{version, rev, updatedAt, main, math, streak}`，`main`/`math` 的结构和旧版 localStorage **逐字节同构** |

> **`streak` 里都记了什么** —— `{streak, lastDate}` 是主字段（当前连胜天数 + 最近一次"有完成"的日期；
> 只看这两天，错过一整天就显示 0）。另外三个是**当天那笔账**的辅助字段，只在"今天完成过东西"时存在：
> `todayDone` 记着今天完成的是哪几天（如 `["main:71"]`），撤勾时用它判断今天还算不算学过；
> `prevStreak` / `prevLastDate` 是**记这一笔之前的样子**，当天完成的天被全部撤光时原样还原。
>
> 进度记录里只有 `tasks`、**没有任何日期**，所以"哪天学的"只能靠这个计数器记 ——
> 勾满和撤勾都必须写，否则把当天全点灭之后连胜还会赖着不走（`_syncStreak` / `_revokeCompletion`）。
> 页面每次启动还会 `_reconcileStreak()` 对一遍账：文件里记着"今天完成过"、但那几天现在都不完成了，就自动退回。

`progress/` **不进 git** —— 它的定位是"由服务端持有的运行时数据"，将来跑在那台 Ubuntu 上，
两台电脑都连同一个服务，就不存在"同步"这回事了。

右下角徽章是你唯一需要留意的状态：

- **绿 `● 已连接 · 进度存于 progress/current.json`** —— 正常，你勾的每一笔都在往文件写
- **黄 `● 未连接 · 进度仅存本浏览器`** —— 服务没起来 / 起的是别的服务 / 直接开的 `index.html`。
  照样能勾，数据存在浏览器里，服务回来 **3 秒内自动同步**
  > 徽章太不显眼，所以这种情况下页面**顶部还会弹一条黄条**，直接写着「你是双击网页文件打开的，
  > 该双击启动器」或者「连不上服务，把终端窗口留着」。点 ✕ 可以关掉。

### ⚠️ 同一时间只在一台设备上编辑

现在是「最后写入者赢」：服务端靠 `rev` 号发现冲突会返回 409，页面会弹窗问你
**用本机这份覆盖文件** 还是 **改用文件里的进度**。它**不会**自动合并 ——
所以别两台电脑同时开着勾。冲突时无论你选哪个，另一份都还在**当天的 history 快照**
和**那个浏览器的 localStorage** 里，不会凭空消失。

## 怎么把老进度搬过来

进度原来是存在浏览器 localStorage 里的，**`file://` 和 `http://127.0.0.1` 是两个不同的 origin**，
换个浏览器、换个打开方式就读不到了。所以要搬只能从**原来那个浏览器**里导出：

**方法一（推荐，一行命令）** —— 在**原来那个浏览器**打开旧页面（`index_old.html` 或 `main/index.html`），
按 F12 打开 Console，粘贴回车：

```js
copy(JSON.stringify({exportedAt:new Date().toISOString(),
  main:JSON.parse(localStorage.plan_tracker_main||'{}'),
  math:JSON.parse(localStorage.plan_tracker_math||'{}')}))
```

然后把剪贴板里的内容存成 `progress/current.json`：

```bash
pbpaste > progress/current.json     # Mac
```

> ~~**方法二（不用 Console）** —— 打开 `index_old.html` → 长按 3 秒导出。~~
> **已删除，别用这条。** 那个长按手势走的是旧版 `app.js`，而它启动时会先把 `d1`–`d33`
> 无条件写成「三天全完成」（`prefillDone33()`，闸门存在 localStorage 里、**按浏览器算**）。
> 在干净浏览器上用它导出，会**凭空多出 33 天假进度** —— 进度文件里那 10 个死键 `d13`–`d22`
> 就是这么来的。该调用已于 2026-10-08 停用（见 `docs/审计-2026-10-08.md`），
> 但这条路径不再推荐，**只用上面的方法一**（直接读 `localStorage`，不经过 `app.js`）。

> 前端会自己做**归一化**，所以旧备份里的 `exportedAt`（而不是 `updatedAt`）、缺 `rev`、缺 `streak`
> 都能直接用 —— 服务端只负责原样存取字节。停在 `progress/` 的 `current.json` **不需要**有 `rev`。

**连胜不迁移**：旧版 Edge 里的 `streakStart_main` 是另一套语义，与现在的 `streak` 不通用，
所以搬过来之后连胜会从下次完成重新起算。

### ⚠️ 老进度的天号对得上吗

计划改过两轮，天号含义变过，搬之前值得知道：

| 版本 | 主计划 | 天号 | 阶段一（Day 1–12） |
|------|--------|------|--------------------|
| `archive/app.js.bak`（最早） | 137 天 | **1–137 连续**（含 13–22） | if/for/while… **语法优先** |
| `app.js` / `index_old.html`（旧版） | 127 天 | 1–12, **23**–137（13–22 已删） | 概念优先，**和现在逐字一致** |
| `main/js/data.js`（现在） | **134 天** | 1–12, 23–**144** | 概念优先 |

- **Day 23–56 三版完全一致** —— 可以直接搬。你备份里的 `d23`–`d48` 全在这一段。
- **Day 1–12**：天号位置没变，但最早那版是「语法优先」的旧内容（if/for/while），
  现在换成了「概念优先」。**你的备份里带着 `d13`–`d22`，而只有最早那版有这 10 天** ——
  所以这批进度最早是在**那一版**上记的。勾的位置是对的，只是 d1–d12 的标题跟当年不一样了。
- **Day 57 往后天号就对不上了**，根子是「阶段三：产品思维」这 8 天（现在占 Day 58–65）是后加的，
  它后面的内容整体往后挪了 8 位；当前版又把原 Day 79、80 两个 RAG 复习日合并。因此：**旧版 Day 58–71 → 现在 Day N + 8；旧版 Day 72 起 → 现在 Day N + 7**。
  只有「缓冲/复习日」这种重名天需要再看上下文。
  两个旧版的分叉点差一天：
  - `app.js` / `index_old.html`：它旧 Day 57 是「痛点识别」，成了现在的 **Day 58**；
    到旧 Day 71 为止是 **+8**（旧 58 → 现 66）；从旧 Day 72 起是 **+7**（旧 137 → 现 144）。
  - `archive/app.js.bak`：它压根没有「阶段三」，Day 57 还是「综合练习」（现在也还是 57）；
    从它 **Day 58** 起也按上面的分段规则换算。
  - 所以**在老版本里学完 Day 58 之后的内容，天号不能直接照搬**，按标题对一遍再手动挪。
- **`d13`–`d22` 是死键**：那是删掉 13–22 之前留下的记录，现在的计划里没有这些天，
  页面不会显示它们，也不会计进"已完成"。留在文件里无害，介意的话删掉即可。
  > ⚠️ **这 10 个键不能用来反推版本**。新版从不删旧键，`app.js` 里的 `prefillDone33()`
  > 还会主动把它们写成 `[true,true,true]`，所以**从 `main/index.html` 新导出的备份同样带着
  > `d13`–`d22`**。上面那条"所以这批进度最早是在那一版上记的"只对 6 月那几份老备份成立。

（这也解释了为什么 6/21 那份备份记着 48 天、页面却只显示 38/135 —— 差的正好是这 10 个死键。
现在这份 10/08 的记着 70 天、显示 60/135，同样差 10。）

### 怎么判断一份备份是不是新天号

`app.js` / `archive/app.js.bak` 里**没有** `reviewed` 这个字段（全仓库 0 次），只有
`main/js/*` 会写。所以备份里只要出现 `{"tasks":[],"reviewed":true}`（数学的复习日），
就说明**是打开 `main/index.html` 记的，天号已经是现在的，不用再 +8**。

## 遇到问题

| 现象 | 原因 / 怎么办 |
|------|----------------|
| **进度全是 0**（总览两个环都是 0/0） | 十有八九是**直接双击了 `main/index.html`**。看地址栏：`file://…` 是错的（够不着进度文件），`http://127.0.0.1:…` 才对。**改用双击根目录的 `启动学习计划.command`** —— 不用自己输端口，它会开好浏览器。页面现在会自己弹一条黄条说这件事 |
| 徽章是黄的 | 服务没起来，或者你开的是 `index.html`。双击启动器即可 |
| 终端窗口关了之后进度变 0 | 服务跟着窗口一起没了。重新双击启动器；如果你在离线期间勾了东西，它 3 秒内会自动同步上去 |
| 点勾了但刷新就没了 | 同上 —— 数据只在当前浏览器里。起服务后会自动同步上去 |
| 双击启动器没反应（Mac） | Gatekeeper 拦了，右键 →「打开」 |
| 提示端口被占 | 服务会自己往后试 20 个端口，看终端打印的实际 URL |
| 想从头开始 | 删掉 `progress/current.json` 再刷新（页面会发现文件空了，然后……**用它自己那份重新播种**，所以你多半还想清一下浏览器 localStorage） |
| 文件写坏了 | 从 `progress/history/` 里拿最近一份好的覆盖回 `current.json` |
