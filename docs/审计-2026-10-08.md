# 项目审计报告

**日期**：2026-10-08
**范围**：整个仓库（`main/` + `tools/` + 历史层 + 部署形态）
**执行者**：Claude Code（三个独立视角的只读审计子代理 + 主会话逐条实测复核）
**结论**：**应用层不需要重构。** 问题集中在「历史层」和「部署层」，共 6 处需要修，其中 1 处安全、2 处会静默丢数据。

---

## 总评

`main/` 那 5 个文件（`data` / `store` / `router` / `render` / `app`）职责单一、分得干净；
`tools/plan_server.py` 用 `mkstemp` + `fsync` + `os.replace` 做原子写、用 `threading.Lock` 串行化读改写、
用 `Content-Type` 探测防止误连 `python -m http.server`。

**这些不是"初学者随手写的"，不要推倒重来。**

真正的问题只有两类：

1. **历史层有毒**：仓库里躺着三代应用、一批跑不通的脚本、一条会凭空伪造进度的迁移路径。
   它的问题不是"乱"，而是**危险**——有两条可复现的路径会把假数据写进 `progress/current.json`。
2. **部署层缺失**：没有任何进程守护，而且服务一断会**静默降级**，进度只活在浏览器里。

## 一、必须修

### ① 任意文件读取（安全）— `tools/plan_server.py:253`

**状态**：✅ 已修

`translate_path` 被覆写后只做了 `normpath().lstrip('/')` 就 `join(WEB_DIR, …)`，
而原注释「SimpleHTTPRequestHandler 自己会挡 `..`」是**错的**——基类靠它自己的实现挡，覆写掉之后就没人挡了。

**实测复现**（只绑 `127.0.0.1`，测完杀进程；只读状态行与长度，未打印敏感文件正文）：

```
GET /index.html                                  → 200 OK
GET /../../../../../etc/hosts                    → 404      （带前导斜杠：normpath 把根以上的 .. 吃掉了）
GET ../../../../../etc/passwd                    → 200 OK   [9350 字节]
GET ../../../../../Users/…/.zshrc                → 200 OK   [1334 字节]
GET ../../../../../Users/…/.claude/settings.json → 200 OK   [478 字节]
```

**为什么会咬人**：带前导 `/` 时逃不出去，所以平时怎么试都打不动；但请求行里的 path **不带前导斜杠**时
完全没有保护。今天默认绑 `127.0.0.1`，外部碰不到——**可一旦部署时绑 `0.0.0.0` 或绑到 tailnet 地址，
能连到那个端口的任何设备就能读服务进程读得到的任意文件**：`~/.ssh/*`、`~/.claude/settings.json`、
各个项目的 `.env`。这比"别人能改我的学习进度"严重得多。

**修法**：换回基类同款逐段过滤。

```python
clean = os.path.normpath(path).lstrip('/')
clean = '/'.join(p for p in clean.split('/') if p not in ('', '.', '..'))
```

### ③ `prefillDone33()` —— 会凭空造出 33 天假进度

**状态**：✅ 已修

**位置**：`app.js:6660`（函数）/ `app.js:6673`（`init()` 里无条件调用）

它把 `d1`–`d33` 全部写成 `{tasks:[true,true,true]}`，唯一的闸门 `plan_prefill_33_done`
存在 **localStorage 里，是按浏览器的**。

而 `readme.md:264-266` 推荐的迁移「方法二」，正是打开旧版 `index_old.html` → 长按 3 秒导出
（`app.js:6538`），导出的就是被它写脏的同一份数据。

**这就是 `d13`–`d22` 的来历**：`prefillDone33` 只写 `d1..d33`，而进度文件里 `d13`–`d22`
确实是 `[true,true,true]`。换台电脑、清缓存、或者将来在 Ubuntu 上第一次用，**它会再咬一次**。

**修法**：停用 `init()` 里那一行（函数本体留着当考古），并删掉 readme 的「方法二」，
把迁移路径收敛到直接读 `localStorage` 的「方法一」。

> 注意：**不要**因此删 `app.js` / `index_old.html`。老进度可能还躺在某个浏览器的 localStorage 里，
> `index_old.html` 是唯一能读它的钥匙。**拆毒，不删除。**

### ④ `scripts/` 全部跑不通，而且会「改了但页面没变」

**状态**：✅ 已修（归档到 `archive/scripts/`）

7 个脚本的路径全写死在 `D:\PY_practice_file\plan`（共 8 处）。
更要命的是：**全仓库没有任何脚本写 `main/js/data.js`**（grep 0 命中）——
**这个 332KB 的数据文件没有生成器，只能手改。**

**为什么会咬人**：如果哪天想批量改计划、去修那些脚本的路径，`sync_math_to_appjs.py`
会**静默重写已经死掉的根目录 `app.js`**，打印 "Successfully updated"，
而页面读的是 `main/js/data.js`——**计划改了，页面一个字没变，且没有任何报错。**

**修法**：`git mv scripts archive/scripts`，并把 readme 里那条
`mine_outline.py → scripts/*.py → main/js/data.js` 的箭头删掉，改成：
「`main/js/data.js` 就是唯一数据源；改计划＝改这个文件。」

**想恢复可复现性的话**：正确方向是反过来——把 `sync_math_to_appjs.py` 的输出目标改成
`main/js/data.js`、路径改成 `Path(__file__).parents[1]`。但这要重跑验证 61 天数据，
**性价比远低于归档**。

### ⑤ 部署：没有进程守护，而且服务一断会静默降级

**状态**：⬜ 未修（部署前做）

仓库里没有任何 systemd unit / nohup / Dockerfile。SSH 上去 `python3 plan_server.py` 一断，服务就死。
而页面**不会报错**——`store.js` 的 catch 会转黄条 + 3 秒重试，勾的东西只写进那台电脑的浏览器。
**整段进度只活在浏览器里，换台机器打开就是 0。**

**顺带一个 systemd 特有的坑**：那个「端口被占就静默向后试 20 个」（`plan_server.py:293`）
在 systemd 下会让 unit **以 active 状态跑在 8001**，而书签指向 8000——
`systemctl status` 是绿的，你却打不开。

**修法**：见 [部署.md](部署.md)。

### ⑥ `flush()` 会丢掉最后一笔勾选 — `store.js:161`

**状态**：⬜ 未修

```js
flush(){
  if(this._inflight||!this._dirty)return;   // ← 在途请求期间直接 return
```

**精确触发路径**：勾 A → 400ms 后发出 PUT、`_inflight=true` → 请求在途时又勾了 B →
重新 arm 定时器 → 定时器到点调 `flush()` → **`_inflight` 为真，直接 return，
而 `_timer` 已经被置 null，没有任何东西再 arm 一次** → PUT 返回时 `store.js:205` 无条件
`_dirty=false`，**B 的脏标记被吃掉**。

本地回环 5ms 撞不上，但**搬到 Tailscale（低配 server + WireGuard，几百 ms）会变成常客**。
更糟的是 `_mirror` 已经置了 `KEY_PENDING='1'`，下次开页面会弹
「本浏览器有还没写进文件的进度，确定覆盖？」——**一个纯客户端调度 bug 被渲染成"你是不是多设备了"的惊吓弹窗。**

**修法**：早退时记一个 `_pendingFlush`，成功回调里补一次 `_schedule()`。**约 3 行。**
