# 双轨学习哲学

> 2026-06-16 · 基于 Day 47-48 的实际学习体验提炼

## 两条轨道的定位

| | 主轨道（Main Track） | 数学轨道（Math Track） |
|---|---|---|
| **定位** | 实战驱动，用到什么学什么 | 学科驱动，从地基一层层往上建 |
| **时间** | 约 3 小时/天 | 约 25 分钟/天 |
| **推进方式** | 项目 → 工具 → 理解 | 概念 → 直觉 → 代码验证 |
| **对数学的态度** | **工具化**：输入什么、输出什么、代表什么、什么时候用 | **理解化**：为什么公式长这样、直觉是什么、和其他概念什么关系 |
| **典型一天** | "今天用 Bootstrap 检验策略——把收益率列表扔进去，看 p 值，p < 0.05 说明可能不是运气" | "Bootstrap = 有放回重抽样。归零是关键——不减均值只能给置信区间，不能做假设检验" |
| **依赖关系** | 不依赖 Math 轨道（自包含） | 不依赖 Main 轨道（自包含） |

## 核心理念

### 1. 两条轨道互相独立

Main 轨道的数学概念以「工具」形态出现——你不需要先学完 Math 轨道的相应内容才能推进 Main。Main 教的是「怎么用」，Math 教的是「为什么」。

```
Main Day 48 学 Bootstrap:
  → 输入: 收益率列表
  → 输出: p值 + 偏离距离
  → 判断: p < 0.05 且样本量足够 → 策略可能有效
  → 这是"黑盒使用"，不需要理解重抽样算法的每一个细节

Math Day 49 学 Bootstrap:
  → 为什么归零后重抽样能模拟"纯运气"？
  → Bootstrap 分布的标准差代表什么？
  → p 值和偏离距离的数学关系
  → 这是"拆开黑盒"，理解背后的数学直觉
```

### 2. syncMain 是信息标签，不是调度命令

`【同步：Main Day X】` 的含义是：**"这个数学概念在 Main 轨道第 X 天第一次用到"**。

它不是"你必须在 Main Day X 之前学完这部分数学"——Main 不需要等 Math。它是一个交叉引用的路标：如果你在 Main Day X 遇到了某个概念，想深入了解它的数学原理，点这个标签可以跳到 Math 轨道对应位置。

### 3. Math 轨道保持学科递进

Math 轨道的 61 天是按照数学学科的认知顺序编排的：

```
函数 → 坐标 → 斜率 → 随机 → 随机变量 → 概率分布 →
正态 → 期望 → 方差 → 相关性 → 样本/总体 → 大数定律 →
CLT → 假设检验 → p值 → 矩阵 → Embedding → ... → Bootstrap
```

这个顺序是数学学习的自然路径。不应该为了匹配 Main 轨道的实战节奏而打乱它。代价是：Main 轨道的一些概念（协方差、Bootstrap）会在 Math 轨道中较晚出现。这不是 bug——Main 先给你工具用，Math 事后给你深度理解。

### 4. 一个概念，两次学习

这不是重复劳动，而是**两次互补的接触**：

| | 第一次（Main 轨道） | 第二次（Math 轨道） |
|---|---|---|
| 深度 | 表层——能用的程度 | 深层——理解的程度 |
| 问题 | "这玩意能干啥？" | "这玩意为什么管用？" |
| 输出 | 跑出结果，看懂结果 | 能口述原理，能指出误区 |
| 时机 | 实战需要的时候 | 数学基础就位的时候 |
| 心态 | 黑盒工具 | 白盒原理 |

**先会用，再理解。** 你在一周内两次接触同一个概念（第一次在 Main 当工具用，第二次在 Math 拆开看），比只接触一次记得牢得多。

## 对开发者的约束

1. **Main 轨道遇到数学概念时**：必须提供"工具化接口"——明确输入、输出、判断标准。禁止只说"用 XX 公式计算"而不解释输入输出。
2. **Math 轨道保持独立性**：不为了追赶 Main 节奏而压缩或打乱教学顺序。
3. **syncMain 标签**：标注 Main 轨道首次使用该概念的位置。允许 Math Day N 的 syncMain 小于 N（概念提前于 Main 使用）或大于 N（概念晚于 Main 使用——此时 syncMain 诚实标注，不造假）。
4. **每次修改 syncMain**：运行 `python validate_sync.py` 验证。
