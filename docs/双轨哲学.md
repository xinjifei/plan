# 双轨学习哲学

## 两条轨道的定位

| | 主轨道 | 数学轨道 |
| --- | --- | --- |
| 目标 | 独立组织构建过程，判断实现与系统行为 | 理解数学直觉、适用边界，用数据支持判断 |
| 时间 | 每天约 3 小时 | 每天约 3 小时 |
| 推进 | 问题、系统与工具之间的关系 | M1–49 建立基础，M50–61 应用巩固 |
| AI 分工 | AI 可协助实现，人负责目标、规则和结果判断 | AI 可协助计算，人负责方法选择、假设与解释 |

两条轨道独立推进，不按同一日期捆绑，也不要求每天同时完成两轨。量化与 AI 是学习载体，目标是可迁移的底层素养，不预定就业方向或最终产品。

## 概念在应用中反复出现

前期建立数学语言；后期围绕实际问题调用它。用均值描述样本、用抽样判断差异、用回归做预测时，都会重新遇到分布和不确定性。重复的价值来自新的判断情境，不是再次背诵定义。

M50–61 每天一个主要问题，不设新概念配额。先尝试、暴露卡点、补足必要理解，再修正结论。完整的跨场景迁移集中在 M52 和 M61 的模块收束中。

## 关联不等于前置要求

`syncMain` 只提供关联位置，不能解释为“必须在主线某天前学完”。旧标签不保证仍是概念首次出现的位置；M50–61 取消强行日期绑定，以前后知识衔接说明为准。

主线遇到数学工具，仍应交代输入、输出和判断边界。数学应用也不要求先完成主线的真实策略、检索系统或 Agent 项目，可以使用小规模、自包含材料。

## 计划与当日教学

plan 保存学习方向、父级目标、衔接与边界；teach 根据当天上下文生成问题、实践与验收。M50–61 按学生自己的分析和选择验收，笔记可以简短，不能只用 AI 产物证明理解。主线原有验收模式不因此改变。

不把显著性当成有效性的充分条件，也不把某一种 Bootstrap 操作当成所有推断的通用步骤。数学方法的使用始终要说明数据与假设。
