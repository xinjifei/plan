# 部署到服务器

目标形态：整包搬到一台 Ubuntu server（无公网 IP，走 Tailscale），服务常驻，
浏览器从任意设备访问同一个地址。

> **这份文档写的是约束和判断点，不是一份照抄的配方。**
> 下面出现的路径、用户名、IP、端口都是**占位示例**。真正的值取决于那台机器，
> 开工前先查，别假设。

---

## 一、先查清现状

后面每个决定都依赖这几个答案：

- 服务器上装了 Tailscale 吗？`tailscale ip -4` 给出什么？
- 打算用哪个用户跑服务？（**建议普通用户，不要 root**）
- 放哪个目录？
- 8000 端口有没有被别的东西占？
- 有没有公网 IP？（"应该没有"不算答案，`ip -4 addr` 看一眼）

---

## 二、必须成立的约束

这几条不是风格偏好，每一条都对应一个真实会踩的坑。

**1. 只监听 Tailscale，不要 `0.0.0.0`。**

这个服务**零鉴权**——谁能连上端口，谁就能读写全部进度。
绑 `100.x` 只有 tailnet 内到得了；绑 `0.0.0.0` 会把公网和同网段邻居一起放进来。
`--host` 填 `tailscale ip -4` 的输出。

**2. `progress/` 的属主必须是跑服务的那个用户。别用 `sudo` 碰它。**

属主不对时，服务读不到文件 → 代码把"读不到"当成"文件不存在" → 前端反过来
**用浏览器里的旧数据覆盖文件**，还提示"已写入"。
你会看到「全是 0 + 一条成功提示」，完全猜不到真因是权限。

`git clone` **不会**带来 `progress/`（它在 `.gitignore` 里），所以进度必须单独搬一次。

**3. 无头机器要 `--no-browser`。**

否则它会去调 `xdg-open`，日志里全是噪音。

**4. 端口冲突要能看见。**

服务默认在端口被占时**静默往后试 20 个端口**。在 systemd 眼里这叫"启动成功"——
于是你会对着 8000 打不开，而 `systemctl status` 是绿的。要么关掉这个回退，
要么部署完确认一下实际监听的是哪个端口。

**5. 先备份 `progress/current.json`。**

它是唯一一份真实进度，**不在 git 里**，丢了就没了。

---

## 三、由你决定的

- 放哪个目录、用哪个用户、绑哪个端口，都可以自己定
- 时区：服务器默认 UTC，而快照文件名用服务器时间、连胜用浏览器时间。
  `timedatectl set-timezone` 调一下能省掉后面一串困惑
- systemd 的加固项（`ProtectSystem=`、`NoNewPrivileges=` 那一类）——
  **能加就加，但不用逐条理解**，它们只是缩小进程能碰到的东西
- 要不要加一条定时的"日终"快照（内置的快照是当天覆盖式的，不是历史）

一个够用的 systemd unit 骨架就长这样，`<>` 里的自己填：

```ini
[Unit]
Description=学习计划进度服务
After=network-online.target tailscaled.service
Wants=network-online.target tailscaled.service

[Service]
User=<跑服务的用户>
WorkingDirectory=<仓库目录>
ExecStart=/usr/bin/python3 <仓库目录>/tools/plan_server.py --no-browser --host <tailnet IP>
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

> `After=tailscaled.service` 别省：绑 `100.x` 时如果 tailscaled 还没起来，
> 绑定会失败，而且报错文案会误导成"端口被占"。

---

## 四、做完怎么算对

别只看 `systemctl status` 是 active。真的走一遍：

1. 浏览器打开页面，进度显示正常（不是 0）
2. 勾一个任务，`progress/current.json` 里 `rev` 变了
3. **重启机器**，等一会儿再打开 —— 服务自己回来了吗？进度还在吗？

第 3 条才是「部署成功」和「这次碰巧起来了」的分界线。

## 五、还没修的

- **前端一个丢勾选的竞态**（`main/js/store.js` 的 `flush()`）：网络延迟大时，
  在请求在途期间勾的那一笔可能不被写盘。本地回环复现不出来，要验证得在
  DevTools 里限速。详见审计报告的 ⑥。
- 其余可选项（CORS、快照语义、时区处理等）见审计报告第二节。

背景、证据、以及"为什么"都在 **[审计-2026-10-08.md](审计-2026-10-08.md)**。
