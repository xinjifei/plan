# 数学课程维护原则

> 2026-11-13 更新。本文件替代旧版“25 分钟、核心/精炼/速览、固定任务数”的生成规则。

## 课程定位

数学轨道保留 61 天。每天约 3 小时，培养直觉、适用边界与实际判断；不要求系统证明定理或独立手写全部代码。

M1–49 保留已学安排与编号，只统一过时的时长表述。M50–61 为应用巩固：每天围绕一个主要问题，调用旧知识，针对实践卡点补讲。允许没有新概念，不固定三个概念、三个实验、三个任务或三条硬线。

## 内容取舍

- M50–51 仅补随机模拟、时间依赖的必要边界，承接分布、相关性与 Bootstrap。
- M52 整合模块四，M53–60 用数据描述、统计证据、预测、相似度、概率预测、优化与组合反复调用旧知识。
- M61 完成模块五整合与跨场景迁移；不要求每天另外做迁移项目。
- 取消 KL、贝叶斯、马尔可夫链、凸优化、决策树、高维空间的独立速览日。正则化只在实际需要时补充基本含义，不作为固定新概念要求。
- 3 小时是实践、解释、反馈和修正的预算；卡点影响判断时先修复，减少其他活动，不靠新增高级名词填满。

## plan 与 teach 的分工

plan 写每日目标、调用的旧知识、关键直觉、适用边界和前后衔接。M50–61 的 prompt 标记 `【学习方式】应用巩固`，`tasks` 为 `[]`，页面使用“标记本日已完成”。空 tasks 只代表计划不预置练习。

具体问题、数据、活动和验收标准由 teach 当天结合学习记录生成，不批量写进 plan。数学应用巩固模式可以依据学生自己的选择、分析、图表解释与互动回答验收，笔记不再是唯一证据；AI 生成结果不证明学生掌握。主线和 M1–49 保留原验收方式。

## 数据与文档

- 运行时事实来源：`main/js/data.js` 的 `MATH_TRACK`。
- `math_outline.py` 是可读大纲镜像，不执行、不作为生成源；`数学轨道思维导图.md` 是摘要。
- `syncMain` 是可选关联，不是调度或硬依赖。M50–61 为 `null`，避免把数学问题强绑到主线某一天；页面需正常呈现无关联日期的行。
- 保持 61 个连续数学天号、模块长度 11/12/16/13/9；不改实际学习进度或练习记录。
- 修改后验证 JS 语法、日数与编号、镜像内容、空任务完成状态，以及 teach 启动与 check 的模式一致性。
- 历史大纲里的“任务”“学习标准”和花括号天号不代表新规则或真实完成状态；已归档脚本不参与当前同步流程。
