# 本地运行与进度维护

## 启动

Mac 双击 `启动学习计划.command`，Windows 双击 `启动学习计划.bat`。两者调用 `tools/plan_server.py`，提供网页和进度读写服务。

从仓库根目录也可以运行：

```bash
python3 tools/plan_server.py
python3 tools/plan_server.py --help
```

默认监听 `127.0.0.1:8000`；以终端打印的实际地址为准。`--port` 可指定端口，`--no-browser` 可关闭自动打开浏览器。使用页面时保持服务终端运行。

直接打开 `main/index.html` 会进入浏览器本地存储模式，不能直接读写进度文件。页面连接徽章会说明当前保存位置。服务恢复后，页面会尝试同步。

## 进度文件

| 位置 | 用途 |
| --- | --- |
| `progress/current.json` | 服务当前持有的主线、数学和连胜进度 |
| `progress/history/<日期>.json` | 按日期保存的快照，不是每次操作的独立历史 |
| 浏览器 localStorage | 离线进度及本浏览器的备份 |

当前文档包含 `version`、`rev`、`updatedAt`、`main`、`math`、`streak`。没有预置任务的课程用 `reviewed` 保存完成标记；历史有任务的课程保留任务勾选记录。

`progress/` 不进入 Git，换机器时需要另行备份或连接同一个服务。课程文件同步不等于进度同步。teach 的当前学习指针也与网页完成记录分开维护。

## 多设备与恢复

服务通过版本号检测写入冲突；页面会要求选择采用文件中的进度还是覆盖为本机进度，不自动合并。因此尽量避免多设备同时编辑。

恢复备份前，先保留当前进度文件和浏览器导出，并停止其他页面继续修改。选用天号与当前课程匹配的备份；重新连接时核对页面载入的是哪一份，避免把浏览器残留的离线记录当作最新进度。不要假定当天快照保留了每一次冲突的双方版本。

旧版本的主线天号和课程内容改动过，不能只按天号或固定偏移盲目迁移。核对标题与所在阶段；存在 `reviewed` 字段也不能证明所有记录都来自同一版课程。

## 从原浏览器导出旧记录

在保存原进度的浏览器和页面来源下，开发者工具 Console 可以直接读取 localStorage：

```javascript
copy(JSON.stringify({
  exportedAt: new Date().toISOString(),
  main: JSON.parse(localStorage.plan_tracker_main || '{}'),
  math: JSON.parse(localStorage.plan_tracker_math || '{}')
}))
```

将结果保存成独立的备份文件，再检查内容与天号。这里不导出连胜状态，不直接覆盖当前进度。不同浏览器、`file://` 与本地 HTTP 地址之间不能共享同一份 localStorage。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 页面进度为空或连接徽章为黄色 | 确认通过启动器进入正确的 HTTP 地址，服务仍在运行 |
| 切换浏览器后看不到离线进度 | 回到原浏览器导出；优先使用本地服务保存到文件 |
| Mac 首次双击启动器被拦截 | 右键启动器，选择“打开” |
| 端口被占用 | 查看终端实际地址，或通过 `--port` 指定另一个端口 |
| 想恢复某一天的进度 | 先备份当前文件，再核对 `progress/history/` 中可用快照与课程版本 |

部署到其他机器见[部署说明](部署.md)。
