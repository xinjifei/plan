# 双轨融合：从并行到统一序列

> 2026-06-16 · 根层对齐方案

---

## 一、问题本质

两个轨道并行推进，但设计哲学不同：

```
当前结构（并行）：
  Main Track (3h/day):  1→2→3→...→46→47→48→...→137
  Math Track (25m/day): 1→2→3→...→10→11→12→...→61
  
  每天两条线同时推进，但 Main 46-48 需要的概念（Bootstrap/协方差）
  在 Math 轨道要几十天后才教到。
```

根本矛盾：**Main 按需驱动（什么时候用到什么时候讲），Math 按学科递进（从地基一层层往上盖）。方向不同，永远无法在并行结构中对齐。**

---

## 二、目标结构

```
统一序列（单轨串行）：
  Main 1→2→...→45 → [Math 4,5,6,8,9,10] → Main 46 → [Math 11,19] → Main 47
  → [Math 12-17,49] → Main 48 → Main 49→...→66 → [Math 24,27,34] → Main 67
  → ... → Main 137
```

**规则：**
- Main 轨道顺序**完全不变**
- 每个 Math Day 插入到**它作为前置知识的 Main Day 之前**
- Math 概念紧邻使用场景，不存在「太早遗忘」或「太晚没教」
- 多个 Math Day 可合并在一天内（每个 25min，同主题连续学习）
- 不紧急的 Math Day 填入 Main 轨道自带的缓冲/复习日

---

## 三、风险分析 & 对策

### 风险 1：上下文窗口溢出
**严重程度：高**

198 天内容（137 Main + 61 Math），每个 prompt 数百到数千字，总数据量远超一次会话。
**对策：递进式修改。** 一次只处理一个模块。用 Python 脚本做批量文本处理，不依赖 AI 逐天编辑。

### 风险 2：修改过程中破坏现有结构
**严重程度：高**

`app.js` 和 `index.html` 依赖特定的数据结构（MAIN_PLAN 分 stages/sections，MATH_TRACK 分 modules）。
**对策：保留现有 app.js 不动，所有修改先在 `math_outline.py` 和 `mine_outline.py` 源文件层面完成，用独立脚本生成新的统一序列文件。仅在最终验证通过后才替换 app.js。**

### 风险 3：前置概念堆积
**严重程度：中**

Main 48（Bootstrap）需要 Math 12-17 + 49 = 8 个前置概念，全部堆在一天前是 200 分钟（3.3 小时），超过每日 3 小时上限。
**对策：允许一个 Main Day 前有多个「Math 前置日」——提前 2-3 天开始铺垫。**

### 风险 4：AI 幻觉导致依赖关系遗漏
**严重程度：中**

当前 DEPENDENCIES 表只覆盖了 14 个 Main Day。可能遗漏了其他 Main Day 的数学依赖。
**对策：在 Phase 1 完成「全量依赖审计」——遍历全部 137 个 Main Day，逐一标注数学依赖。**

### 风险 5：修改后无法回退
**严重程度：低**

**对策：Git 管理。** plan 文件夹已有 `.git` 仓库，每次修改前 commit，失败可回退。

---

## 四、递进式阶段计划

```
Phase 1: 全量依赖审计
  输出: 完整的 Main Day → Math Day 依赖映射表
  时长: 1 次会话

Phase 2: 统一序列设计
  输出: 新的 day-by-day 序列（每天含 Main 或 Math 或 Main+Math）
  时长: 1 次会话

Phase 3: 源文件重组
  输出: 修正后的 mine_outline.py + math_outline.py，或新的 unified_outline.py
  时长: 1-2 次会话

Phase 4: 渲染层适配
  输出: 更新 app.js + index.html 以支持统一序列
  时长: 1 次会话

Phase 5: 验证 & 回退测试
  输出: 验证脚本通过 + 浏览器渲染正常 + Git 可回退
  时长: 0.5 次会话
```

---

## 五、Phase 1 启动条件

进入 Phase 1 前需要确认：

1. [ ] 用户接受「递进式修改」策略（不追求一次全部完成）
2. [ ] 用户确认保留现有 Main 轨道顺序不变
3. [ ] 用户确认 Math 轨道的内部教学顺序可以打破（为了对齐可以重排）
4. [ ] plan 文件夹的 Git 仓库处于 clean 状态

确认后，Phase 1 将：
- 读取全部 137 个 Main Day 的 prompt 文本
- 逐一标注每个 Main Day 依赖哪些 Math 概念
- 输出完整的依赖映射表
